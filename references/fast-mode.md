# 快速模式路径

快速模式用于用户明确说“快速”“直接做”或选择快速出稿的场景。它减少规划、候选和确认步骤，但仍保留会阻止严重错误的结构与渲染校验。快速模式的结果适合先交付可编辑初稿，复杂任务应自动回退到普通 Quick 流程。

## 成本提示

完整模式会读取并整理更多材料、生成完整 `STORY.md`、进行多轮版式与大纲确认，并保留更多候选比较，因此会消耗更多 token 和时间，但可控性更强。快速模式减少这些步骤，适合信息边界清楚、版式要求明确或需要先得到初稿的任务；用户纠偏机会更少，交付后可能需要调整。

启用拓展功能会增加额外 token、处理时间和出错面。图表能力默认可用，但只有资料里存在真实的数据关系时才生成图表；几何底纹必须单独明确允许，正式汇报默认不使用。

## 模式矩阵

| 模式 | 无模板 | 有原始 PPTX 模板 | 保留的检查 |
| --- | --- | --- | --- |
| 完整 | 完整材料摘要、`STORY.md`、设计锁定、多个候选与确认 | 完整模板 inventory、逐页映射与确认 | 全部结构、版式、渲染和视觉检查 |
| Quick | 普通六阶段流程，减少候选数量 | 普通 inventory 后按页填充 | 全部 Hard 检查，允许少量 Soft |
| fast-lite | 一次事实清单、一个 seed、一个候选、直接生成 `deck.json` | 一次紧凑 inventory、自动映射、批量填充并复用 inventory | 结构 Hard 检查、PPTX 可重新打开、真实渲染和明显溢出 |

## 无模板 fast-lite

1. 只整理一次紧凑事实清单：术语、单位、数字、来源、缺口和页数，不另写完整 `STORY.md`。
2. 生成一个可复现 seed，运行：

   ```text
   <py> scripts/sample_style.py --seed <seed> --count 1 --scene <场景> --pages <页数或类型序列>
   ```

   把 seed、候选序号、场景、页型序列、强制颜色和渲染器常量记录到 `style.json`，保证后续能够复现同一候选。
3. 直接取唯一候选，复制渲染器三件套并生成 `deck.json`。不生成完整设计锁定文件，不比较多个候选。
4. 按资料中的真实事实生成页面；随机性只能影响强调色、小范围字号与边距、同等版式候选的 tie-break，不得影响事实、数字、公式、图表数据、模板主题或用户指定颜色。
5. 按顺序运行结构校验、渲染和输出校验：

   ```text
   <py> <渲染器>/deck_check.py deck.json
   <py> <渲染器>/render_pptx.py --input deck.json --output <输出.pptx>
   # deck 含 formula block 或 $...$ 时，在这里运行：
   <py> scripts/formula.py <输出.pptx>
   <py> scripts/validate_pptx.py <输出.pptx> --deck deck.json
   <py> scripts/render_preview.py <输出.pptx> -o <临时目录>/preview --engine officecli --render native --sheet
   ```

   Windows 上必须确认预览使用 `officecli`/`native`；自动回退到 Pillow 只能作为近似检查，不能视为真实预览。缺少真实数据时跳过图表，不用占位数字补齐。

## 有模板 fast-lite

1. 对原始 PPTX 只做一次紧凑 inventory，记录页数、页面尺寸、版式、占位符、标题、页脚、可复用图表和图片位置。
2. 根据标题和 block 类型自动建立 `map.json`，批量填充模板副本；复用同一次 inventory，不重复分析每页。
3. 模板页数、占位符类型、映射覆盖率和输出页数必须通过检查；模板已有图表只保留并填入已有可编辑字段，当前 `template_fill.py` 不改写图表系列、分类和数值。
4. 运行：

   ```text
   <py> scripts/validate_pptx.py <输出.pptx> --deck deck.json --baseline <模板.pptx>
   ```

   再做一次真实预览。模板自身的越界按 baseline 规则降级，新增的 Hard 问题仍必须修复。

## 自动回退

遇到复杂研究、资料缺口、多个模板融合、复杂图片裁切、公式密集页、复杂动画、需要重写模板图表数据或用户要求精细视觉控制时，停止 fast-lite，回退到普通 Quick 或完整模式，并在材料摘要中记录原因。

## fast-lite 仍必须阻断的错误

- JSON 无法解析、`slides` 为空、未知 block kind 或必填字段缺失。
- 行内公式 `$` 不成对、图片路径不存在、公式替换失败。
- block 或形状越界、零尺寸、明显文本溢出、严重重叠。
- 图表的分类/系列长度不一致、非有限数值、重复系列名、禁止双轴，或多系列缺少来源和可访问性说明。
- PPTX 无法重新打开、模板页数或映射不一致。

快速模式可以减少正文最低字数、版式种类、结构页和多轮审美确认等软性门槛，但不能跳过事实缺口门，也不能用随机内容填充缺失信息。
