# 阶段一：阅读材料（source-intake）

> 设计要求：严格遵循模板——先分析页面比例/母版版式/页眉页脚页码/主辅色/分隔线色块装饰/图片放置逻辑/
> 各类型页版式规律，优先复用模板已有版式；先判断领域、汇报场景、目标听众，按领域通行惯例组织内容；
> 内容顺序尊重原始资料逻辑，重组时**不增删核心信息**；图表文字结论相互印证、数据口径一致；
> 资料不足的部分如实指出缺口，不编造内容填充。

## 1. 素材读取

| 素材类型 | 方式 |
|---|---|
| 纯文本 / Markdown | 直接读 |
| Word (.docx) / PDF / Excel (.xlsx) | 用 Read 工具直接读（支持解析） |
| HTML / 网页 URL | `scripts/source_to_md.py <文件或URL> [-o out.md]` 转 Markdown 后读 |
| CSV / TSV | 直接按表格读 |
| 图片 | 用 Read 工具看内容（必要时 OCR），记录到材料摘要；能否放进 PPT 取决于阶段二用户是否允许复用资料图片 |
| 复杂或转换失败 | 如实列缺口问用户，不编造内容填充 |

读取后**校验转换结果**：数字、单位、公式、专业术语不能因转换而失真；有疑问回原文件核对。

### PDF 读不出时（提示受密码保护、乱码、只有扫描图）

先装 PyMuPDF（走清华源，装进项目 venv）：

```
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple pymupdf
```

```python
import pymupdf
doc = pymupdf.open("论文.pdf")
text = "\n\n".join(f"[第{i}页]\n{p.get_text()}" for i, p in enumerate(doc, 1))   # 抽全文，再按页读
page = doc[3]                                                                      # 第 4 页
page.get_pixmap(dpi=200, clip=pymupdf.Rect(70, 90, 540, 360)).save("fig4.png")     # 按坐标（pt）裁出一张图
```

先把整页渲染成 PNG（`page.get_pixmap(dpi=120).save(...)`）用 Read 看，确认图在页面上的位置再裁；矢量图没有嵌入图片，只能按坐标裁。扫描件没有文字层，抽出的文本为空，只能看渲染图并如实列缺口。

**复用资料图片的限制**：只用清晰、单张的图（折线图、流程图、架构图）；裁出后分辨率要够显示宽度（validate 会查）。多子图拼图（a)(b)(c) 并排）放进图片框会被缩得看不清，不适合复用，改用文字或重新画；图注要保留原图编号并注明来源。

## 2. 领域与场合判断

动手前先回答三件事，并记入 `材料摘要.md`：

1. **领域与行业**：学术 / 工程技术 / 商务咨询 / 政务公共 / 教育培训，以及更细的学科或行业。
2. **汇报场景**：答辩 / 申报 / 评审 / 会议 / 汇报 / 教学 / 投标 / 路演。
3. **目标听众**：专家评委 / 领导 / 客户 / 学生。

按领域惯例组织：
- 学术：背景—问题—方法—结果—结论—意义；术语规范、数据严谨、引用清晰。
- 工程技术：总体架构、关键流程、技术参数与验证结果；善用技术路线图、架构图、流程图。
- 商务咨询：结论先行，数据支撑，突出洞察、建议与行动项。
- 工作总结：按主题或时间组织，条理清晰，突出量化成效。
- 教学培训：由浅入深，概念图解，案例先行。

## 3. 模板分析（有模板时必做）

用 `scripts/analyze_template.py <模板.pptx> -o 模板摘要.md` 自动提取，并**人工补全以下内容**。完全遵循模板和半自主时都要做模板 inventory：前者用 OfficeCLI 编辑模板副本（见 `template-inherit.md`），后者还要记录内容页母页候选和可复制的顶层组合（见 `template-semi-autonomous.md`），所以模板里哪些原页可复用、各页有哪些内容 key 要在这里理清：

- [ ] 页面比例及尺寸（自动）
- [ ] 母版和版式结构：有哪些可用版式、各自用途（自动提取名称与占位符）
- [ ] 主色、辅助色（自动提取主题色）
- [ ] 页眉、页脚、页码的位置与样式
- [ ] 分隔线、色块及装饰元素：哪些是母版固定元素、放在哪
- [ ] 图片放置逻辑：图片出现的位置、大小规律、是否留白
- [ ] 各类型页面的版式规律：标题页/目录页/章节页/正文页/图文页/表格页/总结页分别长什么样

结论写入 `模板摘要.md`：**新 PPT 优先复用模板已有版式，不因内容不同就重新设计整套视觉系统。**

### 3.1 模板动画 inventory（阶段一必做）

无论用户是否启用可选动效，只要输入包含模板，就在阶段一对同一份只读 `power_pptx Presentation` 运行 `scripts/animation_inventory.py` / `inventory(prs)`。必须分别检查并记录：

- `slideMasters`、`slideLayouts`、实际 `slides` 三层；每页的 source part、master/layout 关系；母版或版式时序的继承关系。
- 每个部件的 `p:timing`、`p:bldLst`，包括 `mc:AlternateContent` 的 Choice/Fallback 子树；按本部件 `cNvPr` ID 域解析 shape target，记录可解析的形状名/key、悬空 ID 与歧义 ID。
- 触发事件（如 `onClick`）、段落/字符范围、`mainSeq`/`interactiveSeq`，以及 motion、media、command 和无法解释的高级特性。
- 转场单独记录类型、时长、自动翻页、Morph 和声音标记，不把转场当作对象时序。

这是静态 XML 清单，不代表实际播放已验证。阶段一只登记风险和语义指纹输入，不在发现悬空目标时自动清理整页。悬空目标、未知高级时序、共享层继承、段落构建和 Morph 风险必须进入前置动效计划；由 `auto`、`preserve` 或 `strip` 决定是否允许后续编辑。

若使用模板母页或模板填充，manifest/map 顶层可写 `animation_policy`，每个输出页可写同名覆盖，取值为 `auto`、`preserve`、`strip`。CLI 的 `--animation-policy` 覆盖全局默认，但逐页覆盖仍优先。需要先审阅计划时使用 `--animation-plan-only`；它只输出编辑前计划，不调用 OfficeCLI。

## 4. 充分性检查（信息缺口门）

整理 `材料摘要.md` 时逐项核对：

- 术语、名称、单位、数字是否完整、与原文一致。
- 数据图表所需数值是否齐备（缺原始数值的图表无法画，先记录缺口）。
- 关键结论是否有资料支撑；"显著 / 领先 / 国际先进"等修饰有没有出处。
- 页数与内容量是否匹配：内容太少不硬凑，内容太多考虑合理拆页。

⛔ **信息缺口门**：把缺口整理成清单（缺失项 / 影响 / 需要用户提供什么），问用户补齐或确认如实留白。
**不编造数据、结论、案例**。

## 5. 产物：材料摘要.md

```markdown
# 材料摘要
- 领域/场景/听众：...
- 资料来源：...（文件名，如有）
- 模板摘要：有（见 模板摘要.md）/ 无
- 用户选择（阶段二）：模板风格模式 完全遵循/半自主/完全自主白底极简/完全自主用户指定；模式 完整/Quick/fast-lite；允许复用资料图片 是/否；统计图表 默认开启（仅真实数据关系）；拓展 动效/几何装饰角饰/特殊排版/无；模板 `animation_policy` 默认 `auto`/`preserve`/`strip`，逐页覆盖；几何底纹 明确允许/不允许

## 事实清单
（按主题列出：每个事实一句话，带来源位置，数字/单位/术语逐字摘录）

## 关键术语与数据
（表格：术语/数据 | 原文出处 | 备注）

## 内容顺序
（原始资料的组织顺序；如要重组，说明重组依据与不增删原则）

## 信息缺口
- [ ] 缺口 1：...（需要用户提供...）
```
