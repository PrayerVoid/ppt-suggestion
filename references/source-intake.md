# 阶段一：阅读材料（source-intake）

> 设计要求：严格遵循模板——先分析页面比例/母版版式/页眉页脚页码/主辅色/分隔线色块装饰/图片放置逻辑/
> 各类型页版式规律，优先复用模板已有版式；先判断领域、汇报场景、目标听众，按领域通行惯例组织内容；
> 内容顺序尊重原始资料逻辑，重组时**不增删核心信息**；图表文字结论相互印证、数据口径一致；
> 资料不足的部分如实指出缺口，不编造内容填充。

## 1. 素材读取

| 素材类型 | 方式 |
|---|---|
| 纯文本 / Markdown | 直接读 |
| Word (.docx) / PDF / Excel (.xlsx) | 用 Read 工具直接读（支持解析） |
| HTML / 网页 URL | `scripts/source_to_md.py <文件或URL> [-o out.md]` 转 Markdown 后读 |
| CSV / TSV | 直接按表格读 |
| 图片 | 用 Read 工具看内容（必要时 OCR），记录到材料摘要 |
| 复杂或转换失败 | 如实列缺口问用户，不编造内容填充 |

读取后**校验转换结果**：数字、单位、公式、专业术语不能因转换而失真；有疑问回原文件核对。

## 2. 领域与场合判断

动手前先回答三件事，并记入 `材料摘要.md`：

1. **领域与行业**：学术 / 工程技术 / 商务咨询 / 政务公共 / 教育培训，以及更细的学科或行业。
2. **汇报场景**：答辩 / 申报 / 评审 / 会议 / 汇报 / 教学 / 投标 / 路演。
3. **目标听众**：专家评委 / 领导 / 客户 / 学生。

按领域惯例组织：
- 学术：背景—问题—方法—结果—结论—意义；术语规范、数据严谨、引用清晰。
- 工程技术：总体架构、关键流程、技术参数与验证结果；善用技术路线图、架构图、流程图。
- 商务咨询：结论先行，数据支撑，突出洞察、建议与行动项。
- 工作总结：按主题或时间组织，条理清晰，突出量化成效。
- 教学培训：由浅入深，概念图解，案例先行。

## 3. 模板分析（有模板时必做）

用 `scripts/analyze_template.py <模板.pptx> -o 模板摘要.md` 自动提取，并**人工补全以下内容**：

- [ ] 页面比例及尺寸（自动）
- [ ] 母版和版式结构：有哪些可用版式、各自用途（自动提取名称与占位符）
- [ ] 主色、辅助色（自动提取主题色）
- [ ] 页眉、页脚、页码的位置与样式
- [ ] 分隔线、色块及装饰元素：哪些是母版固定元素、放在哪
- [ ] 图片放置逻辑：图片出现的位置、大小规律、是否留白
- [ ] 各类型页面的版式规律：标题页/目录页/章节页/正文页/图文页/表格页/总结页分别长什么样

结论写入 `模板摘要.md`：**新 PPT 优先复用模板已有版式，不因内容不同就重新设计整套视觉系统。**

## 4. 充分性检查（信息缺口门）

整理 `材料摘要.md` 时逐项核对：

- 术语、名称、单位、数字是否完整、与原文一致。
- 数据图表所需数值是否齐备（缺原始数值的图表无法画，先记录缺口）。
- 关键结论是否有资料支撑；"显著 / 领先 / 国际先进"等修饰有没有出处。
- 页数与内容量是否匹配：内容太少不硬凑，内容太多考虑合理拆页。

⛔ **信息缺口门**：把缺口整理成清单（缺失项 / 影响 / 需要用户提供什么），问用户补齐或确认如实留白。
**不编造数据、结论、案例**。

## 5. 产物：材料摘要.md

```markdown
# 材料摘要
- 领域/场景/听众：...
- 资料来源：...（文件名，如有）
- 模板摘要：有（见 模板摘要.md）/ 无

## 事实清单
（按主题列出：每个事实一句话，带来源位置，数字/单位/术语逐字摘录）

## 关键术语与数据
（表格：术语/数据 | 原文出处 | 备注）

## 内容顺序
（原始资料的组织顺序；如要重组，说明重组依据与不增删原则）

## 信息缺口
- [ ] 缺口 1：...（需要用户提供...）
```
