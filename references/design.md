# 视觉 / 版面 / 密度（写 deck.json 之前必读）

> 设计要求：整体视觉专业、克制、简洁；装饰只用简单圆点/线条/卡片，几何图形只在边角或封面/目录/
> 章节空白处；无模板时白底为主、辅助色低饱和掺 G、同级统一；全文统一一种中文字体；图表数据
> 能图不字、优先原生可编辑图表、要素完整、配色继承；排版对齐、留白、层级清晰，页眉页脚页码沿用。

deck.json 的字段结构在 `deck-schema.md`；模板模式在 `template-inherit.md`。

配色、字号、间距由渲染器写死。JSON 里**不要**出现 color / fontSize / hex。

## 1. 视觉 DNA（无模板时）

专业、克制、简洁，像该领域专业人员手工制作：

- 用户不说明则建议以白底为主。封面/目录/章节页允许在**空白边处**加简单几何形状重叠形成的装饰（几何图形，小范围可以加点、线之类的，大范围可以加几何图形，尤其是当用户要求“美观”、“炫酷”时需要加），装饰只在空白处。正文页的边角也可以增加与封面/目录/章节页边角处对应的装饰，但一定不要遮挡文字，也不要喧宾夺主。
- 强调色由渲染器写死为**单套低饱和色**（RGB 掺 G、低亮度、避免纯色），同一页少量色调；同级字段配色统一且尽量黑色，用字号/字重区分层级。
- 不用阴影、不用 3D、不用发光、不用渐变。
- 正文标题是完整结论句，不是关键词标题。
- 有模板时：**渲染器继承模板**的页面比例、母版版式、配色、装饰与图片放置逻辑，不重新设计一套。

## 2. 禁止（硬性）

- 暗色背景（典型 AI 特征）
- 互联网宣传风、商业路演风
- 莫名其妙的彩色边框、彩色文字、彩色小标题
- 鲜艳颜色、渐变、大面积发光、复杂背景纹理
- 大量圆角卡片；每页机械地 3～4 个卡片
- 「标题 + 若干同尺寸卡片 + 图标」的 AI 卡片模式
- 为填满页面加无意义图形；过度使用图标
- 每页「小字彩色页标题 + 大字黑色主标题」的 AI 排版
- 装饰大于内容
- 图表外额外嵌套一层冗余圆角卡片

## 3. 字体

- 全文统一一种中文字体（微软雅黑、楷体等），标题/正文/表格/图注/页脚/流程图/图表标签/形状文字都不混用。
- 英文与数字原则上同字体；中文字体不适合英文时（如楷体）用 Times New Roman。
- 数学公式、化学式、代码按学科规范，不受上述限制。

## 4. 密度是第一优先级

看起来单薄，九成是**内容不够**，不是样式不够。每页的下限：


| 页       | 下限                                                                             |
| ---------- | ---------------------------------------------------------------------------------- |
| 封面     | 主标 + 副标 + 3–5 个短标签（用 `·` 分隔）                                      |
| 目录     | 3–8 条，每条有编号、章名、一句摘要（`note`）                                    |
| 章节扉页 | 大号编号 + 章名 + 一句副标                                                       |
| 结构页   | `layers` / `pipeline` / `hub` / `timeline` / `steps` 占主体，每个节点都有 `body` |
| 数字页   | 3–4 个 `stats`，每项 `value` + `label` + `note`，必要时加一条 `insight`         |
| 卡片页   | 每卡一句判断，全稿 ≤ 2 页，且不连续两页                                         |

正文页正文总字数低于 110 字会被 `deck_check.py` 挡住。每个条目的 `body` 低于 10 字也会被挡住。

## 5. 怎么把内容写厚

- 一个模块名 → 写清「做什么 / 谁在用 / 不做什么」。
- 一个流程节点 → 写清「输入、判定规则、输出」。
- 一个数字 → 写清「相对谁、意味着什么」。
- 一个阶段 → 写清「产物是什么、怎么验收」。

写不出来就说明信息不足：合并这一页，或者回阶段一问用户。不要用空话凑版面。

## 6. 页面节奏与版式多样性

- 相邻页版式不能相同；等宽卡片全稿最多 2 页，且不能连续两页。
- 至少 40% 的页用非对称或结构版式（`split` / `layers` / `pipeline` / `hub` / `compare` / `rows` / `stats`）。
- 全稿至少 2 页结构页（`layers` / `steps` / `rows` / `pipeline` / `hub` / `timeline` / `compare`）。
- `insight` 全稿 3–6 条，别每页都放。
- 不要让每一页长得完全一样：单栏、双栏、左文右图、左图右文、上图下文、表格、时间轴、流程图、技术路线、框架、图表、组织架构、关键数字，按内容选。
- 同页元素按统一基准线对齐，页面边距一致；标题、正文、图表间留呼吸空间。

## 7. 美学基线（默认排布规范）

以下默认值在渲染器中落实，规划时用于判断密度是否合适：

- **行距节奏**（多行文本）：多行标题 1.2–1.3× 字号；小字/密集正文 1.4–1.5×；普通正文 1.5–1.6×；稀疏页 1.6–2.0×。段间间距 > 行内间距，列表项间距 < 段落间距。
- **对比与可读性**：语义文字与背景必须可区分；低对比只用于次要元数据（脚注、页码等）。
- **对齐与邻近**：相关标题、正文、标签、节点对齐到同一轴线；同组元素比异组更近，间距承载层级。
- **视觉重量**：由面积、明度、密度共同决定焦点；对称可选，刻意失衡可制造方向。
- **容器**：卡片/面板表达分组、层级或边界；同层容器同处理，除非语义差异需要对比。**不搞无计划的 web 卡片网格**。
- **数字与标点**：小数、千分位、百分号、引号跟随内容语言，一个语言一个选择、全文一致。
- **自然换行**：在语义断点换行；避免机械等宽行或孤立的单字行。

## 8. 图表与数据

- 能用图讲清楚的不大段文字；能用表格对比的不逐条罗列。
- 数据图表优先用 PPT 原生可编辑图表，而不是截图或图片。
- 图表类型匹配数据关系：趋势折线、对比柱状、构成饼图/堆积、流程流程图、演进时间轴。
- 图表要素完整：坐标轴名称、单位、图例，必要时数据来源；数据标注不过度密集。
- 图表配色继承模板主色与辅助色（无模板用渲染器单套强调色），不引入新颜色。
- 能直接引用资料中现有图片就引用，不重绘、不用大段文字说明；图表外不嵌套冗余圆角卡片。
- 引用图片保持清晰完整，不拉伸变形、不残留水印。
