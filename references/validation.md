# 结果校验（阶段四使用）

> 设计要求：输出自查覆盖排版（文字重叠/遮蔽、图形卡片列表交叠）、图片（模糊、拉伸变形、不清晰）、
> 信息量（过低或过高）、信息一致性（错别字、术语一致、数据矛盾、图文不符、编造或无来源信息）；
> 排版对齐、间距、层级、页眉页脚页码、图片等比、表格简洁；资料不足如实指出缺口，不编造填充。

校验分两层：**脚本机械检查**（`validate_pptx.py`，Hard/Soft 分级）+ **模型对照清单自查**（本文件 §2）。
全部 Hard 通过才交付。

## 1. 脚本机械检查（validate_pptx.py）

对渲染产出的 `.pptx` 逐页检查，报告按 **Hard（必须修）/ Soft（明显不好才动）** 分级输出，有问题退出码 1。

### Hard（必须修）

| 项 | 说明 |
|---|---|
| 形状重叠 | 两形状实际占用区域相交面积 > 28% 小者（透明文本框按文字占用估算，面板内文字/装饰条豁免） |
| 元素越界 | 形状超出幻灯片画布边界 |
| 文本框溢出估算 | 按字号与宽度估算行数超过文本框高度 25% + 0.15 in |
| 零尺寸形状 | 有填充但宽高 ≤ 0.01 in |
| 图片纵横比失真 | 显示比例与原生比例偏差 > 10% |
| 图片分辨率过低 | 原生宽像素 < 显示宽像素 × 55% |
| 连续同版式 | 相邻正文页 block 版式完全相同（配 --deck 时） |
| 页数不一致 | deck 页数与 pptx 页数不符（配 --deck 时） |

### Soft（--strict 时也失败）

| 项 | 说明 |
|---|---|
| 文本溢出疑似 | 估算高度超框但幅度不大（按阈值内） |
| 图片略糊 / 略变形 | 未达 Hard 阈值但值得肉眼复核 |

## 2. 模型自查清单（逐页过一遍）

### Hard（必须修）

- **越界**：元素超出页面。
- **文字溢出容器**：文字超出所在面板/卡片/文本框。
- **文字互相重叠**：两个文字块实际文字碰撞。
- **可读性**：正文与背景对比不足（小字 ≥ 4.5:1、大字 ≥ 3:1 的意识）；文字压在复杂图片上无底衬。
- **元素碰撞**：图形与图形叠压且破坏语义。
- **页眉页脚页码**：模板已声明的页眉、页脚、页码被遮挡/移动/删除。
- **图片损坏**：图片打不开、严重变形、拉伸。
- **关键元素缺失**：deck 要求的核心图形/表格/数据缺失。
- **信息一致性**：错别字、术语不一致、数据前后矛盾、图文不符、编造或无来源信息。
- **重叠遮蔽**：文字重叠、图形/卡片/列表交叠。

### Soft（明显不好才动；拿不准就保持）

- **垂直节奏过紧**：连续文本行距 < 1.05× 字号 → 放到 1.15–1.3×。
- **垂直节奏过空**：块内 > 大片无意义留白。
- **对齐漂移**：同列 x 或同行基线明显不在一条线上 → 对齐。
- **网格不均匀**：一排卡片间距相差 > 5% → 重新分布。
- **CJK 字距过大**：letter-spacing 超过字号 5% → 收小。
- **装饰色竞争**：多个装饰色互相抢眼、与强调色打架 → 并入已有强调色。
- **强调焦点不符**：页面最显眼的不是 deck 里声明的主信息 → 调整。
- **图文关系**：图注离图超过 60px、图上有字无底衬、图片无用途 → 收紧/加底衬/删。
- **版式单调**：连续多页长得一样 → 换版式。

### 不触碰

- 配色、字体等**品牌级决策**不改（要改回阶段一/改渲染器常量，全稿统一改）。
- **结构重排**（列数、图表类型、章节）不在此阶段做。
- **内容增删**不做——本阶段只允许位置、字号（角色锚点 ±2pt 内）、间距、对齐、底衬调整。
- 文字提炼不得改变原意。

## 3. 修复回路（就地修复，不推倒重来）

| 问题层 | 修哪里 | 然后 |
|---|---|---|
| 内容/文案问题（错字、术语、数据、句子 AI 味） | 改 `deck.json`（必要时改 `STORY.md`） | 跑 `deck_check.py` → 重渲染 → 重校验 |
| 版式问题（重叠、越界、溢出、版式单调） | 改 `deck.json` 的 layout/block 安排 | 同上 |
| 渲染器 bug / 视觉规则不符 | 改 `scripts/render_pptx.py` 或 `text_measure.py` | 重渲染该页或全稿 |
| 模板继承问题 | 检查模板分析是否正确，调整 deck.json 的 type/layout 匹配 | 重新渲染 |

每次修复后重跑：`deck_check.py deck.json` → `render_pptx.py` → `validate_pptx.py`，直到 **Hard 为零**（Soft 允许，但 `--strict` 场景除外）。
交付时如实说明资料缺口与假设。
