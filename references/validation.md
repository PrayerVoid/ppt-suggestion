# 结果校验（阶段六使用）

> 设计要求：输出自查覆盖排版（文字重叠/遮蔽、图形卡片列表交叠）、图片（模糊、拉伸变形、不清晰）、
> 信息量（过低或过高）、信息一致性（错别字、术语一致、数据矛盾、图文不符、编造或无来源信息）；
> 排版对齐、间距、层级、页眉页脚页码、图片等比、表格简洁；资料不足如实指出缺口，不编造填充。

交付检查依次覆盖 **包结构与引用完整性 → 逐页机械检查 → 逐页渲染目视检查 → 目标应用兼容性**。任何一层发现 Hard 都必须修复，脚本通过不能覆盖目视发现的问题。目标应用实际打开与前面的检查分别记录；未在用户指定的 Office 中打开过，必须写明“未验证目标应用打开”，不能声称“无修复提示”。

模板生成器在临时副本中编辑。`template_fill.py` 先检查替换文字容量和替换图片源分辨率，再按编辑前动画计划应用 `auto`/`preserve`/`strip` 动作，最后检查包结构；它还会检查内容落位、组合尺寸和文字布局。失败不覆盖上一次成功输出。生成路径调用 `repair_package(repair_animations=False)`，只更新页数等 metadata；动画/构建悬空、缺失关系、重复 ID 或其它动画错误均阻断，不由包修复器自动整页清除。公式后处理完成后仍须跑下述最终检查，并重新核对动画计划。

容量门禁按显示尺寸估算模板文字框，覆盖普通字段、竖排标签、不换行文字和 `clone_groups` 缩放后的子形状。源图按原生像素与显示像素比较，低于 70% 有效分辨率直接阻断；模板原有图片不因 baseline 自动豁免，替换图片必须重新检查。没有 Pillow 时脚本仍可读取 PNG/JPEG 头部；若无法识别尺寸，会明确报错，不把未知图片当作清晰图片通过。

## 动效前置计划与最终核对

模板动画的扫描范围、策略、CLI 优先级、前置计划与阻断规则统一见 [template-animation.md](template-animation.md)。最终校验保留以下执行要求：所有公式、图表和形状后处理完成后核对适用动画计划，不以静态检查代替实际播放。

编辑后运行：

```bash
python scripts/template_animation.py 输出.pptx --plan 输出.pptx.animation-plan.json
```

生成后的核对会验证目标、时序、转场以及版式/母版关系的归一化语义指纹。新增动效必须取得明确授权并重建计划；其结果不能沿用模板编辑前指纹声称新增效果已经验证。动效计划核对通过仍只说明结构语义一致，不能声称放映播放成功。

交付报告将四类证据分开记录，建议使用 `references/playback-report.md` 作为记录模板：

1. **结构**：ZIP/XML、关系、shape ID、动画目标、构建列表、时序依赖和计划核对。
2. **打开**：是否由目标 PowerPoint/WPS/LibreOffice 实际打开，以及是否出现修复提示；没有实测就明确写未验证。
3. **静态渲染**：`render_preview.py` 使用的引擎、公式/图表限制和逐页目视结果；渲染器看不到动画时不据此判断播放。
4. **实际放映**：是否在目标应用进入放映并检查点击、自动翻页、声音、Morph 和交互；没有实测时写明未验证，不以静态检查替代。

## 1. 脚本机械检查（validate_pptx.py）

对渲染产出的 `.pptx` 逐页检查，报告按 **Hard（必须修）/ Soft（明显不好才动）** 分级输出，有问题退出码 1。

### Hard（必须修）


| 项             | 说明                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------ |
| 形状重叠       | 两形状实际占用区域相交面积 > 28% 小者（透明文本框按文字占用估算，面板内文字/装饰条豁免）。两个透明文本框都按"文字溢出框底后的真实占用"比较，所以标签折行压到下一段说明文字、`stats` 卡片文字压到后一个块都会报 Hard |
| 元素越界       | 形状超出幻灯片画布边界                                                                   |
| 公式未转换     | 任意文字（含组合形状、表格单元格）里还留着成对的 `$...$`，先跑 `formula.py`；`\$` 与单个孤立的 `$` 不算 |
| 文本框溢出估算 | 递归检查组合内部文字，换算各层 off/ext/chOff/chExt；扣内边距，计入显式字号、字符间距、换行、行距及段前段后。估算高度 > 框高 + max(0.04 in, 框高×10%) 为 Hard；不换行文字超过可用宽 0.04 in 也为 Hard；检查异常必须报错 |
| 包结构与引用 | 内部关系目标存在、页内形状 ID 唯一、动画与构建列表的 spid 指向本页现存形状；模板删除内容后不可保留悬空动画。动画计划还须核对目标、时序、转场和版式/母版关系的归一化语义指纹 |
| 原生图表 GraphicFrame | 检查图表整体 bbox、零尺寸、越界、重叠、图表类型、系列数、系列数值、图例与原生标题；图表内部标签仍需真实 Office/LibreOffice 预览 |
| 零尺寸形状     | 有填充但宽高 ≤ 0.01 in                                                                  |
| 图片纵横比失真 | 显示比例与原生比例偏差 > 10%                                                             |
| 图片分辨率过低 | 原生宽像素 < 显示宽像素 × 55%                                                           |
| 连续同版式     | 相邻正文页 block 版式完全相同（配 --deck 时）                                            |
| 页数不一致     | deck 页数与 pptx 页数不符（配 --deck 时）                                                |

### 模板模式：`--baseline`

模板自带的装饰形状可能本来就出血越界或互相重叠，这些不是内容造成的。模板模式校验时加上原模板：

```
python scripts/validate_pptx.py "<输出的.pptx>" --baseline "<模板.pptx>"
```

模板原有的出血越界按形状名和位置比对；重叠按名称、尺寸和相对位置比对，允许原有装饰组合整体平移。匹配项列为“模板自带，已忽略 N 项”。两个文字对象的重叠还必须匹配原始文字，换了文字不能继承旧碰撞豁免。文字装不下、零尺寸、包引用错误永不豁免。模板模式没有 `--deck` 的 block 信息时，版式签名比较自动跳过。

文字测量属于保守估算，字体回退、继承字号、旋转或翻转组合等情况必须以真实渲染复核。不要根据估算通过推断 PowerPoint 内的换行一定一致。

### Soft（--strict 时也失败）

名为 `FORMULA_` 开头的占位框、含原生公式（`m:oMath`）的形状不参与文字溢出估算，`DECO_` 开头的装饰形状不参与重叠与溢出检查，越界检查对它们仍然生效。公式显示是否正常以出图为准。


| 项                | 说明                               |
| ------------------- | ------------------------------------ |
| 文本溢出疑似      | 估算高度超框但幅度不大（按阈值内） |
| 图片略糊 / 略变形 | 未达 Hard 阈值但值得肉眼复核       |
| 页数元数据过期 | app.xml 中 Slides/Notes 与部件数量不符；模板生成器会自动更新，单独出现不代表文件损坏 |

## 2. 模型自查清单（如果支持视觉，则一定要将每页渲染成图片逐个过一遍）

### 2.0 先把每页渲染成图片

```
python scripts/render_preview.py "<输出的.pptx>" -o <系统临时目录>/ppt_preview --sheet
```

然后用 Read 工具看 `sheetN.png`（每张 2x2 共 4 页），有疑点的页再看单页 `sNN.png`。预览放系统临时目录（如 Python `tempfile.gettempdir()`），不要放进交付文件夹。

`render_preview.py` 默认 `--engine auto`：用 officecli 逐页截图；找不到 officecli 时退回内置近似渲染。stderr 会打印实际使用的引擎。

| 引擎 / 渲染 | 前提 | 效果 |
| --- | --- | --- |
| `officecli` + `--render html`（默认） | 已装 officecli 与 Edge/Chrome 等浏览器 | 跨平台、结果可复现，字体、换行、图表能看到。**原生公式会画成 LaTeX 源码文字**，公式页不能用它判断公式是否正确；还会多画母版里的日期/页码占位，这两点都是渲染假象，不是 pptx 里的内容 |
| `officecli` + `--render native` | Windows 且已安装 PowerPoint | 调用 PowerPoint 真实渲染，公式按数学排版显示，没有多余占位，最保真，也更慢 |
| `pillow` | 只要 power_pptx + Pillow | 按形状位置近似绘制，看不到公式（原生公式形状会被跳过并在 stderr 提示）和动画，字体和换行与 PowerPoint 有出入。能看出重叠、溢出、失衡 |

含公式的页用 `--render native` 出图复核；没有 PowerPoint 时，html 只能检查公式框的位置与大小，公式本身是否排对要在交付说明里写明"未经真实渲染"，并让用户在 PowerPoint 里打开确认。

用了 `pillow` 引擎时，交付说明里要写明“未经真实渲染”。HTML 和 Pillow 都不会触发 PowerPoint 的文件修复机制，预览正常、`officecli validate` 通过也不能证明 Mac Office 打开无修复提示。目标应用可用时实际打开生成副本，核实修复提示并逐页查看；无法实测则如实说明范围。

officecli 的常驻进程会延迟落盘，脚本已在读文件前 close，手动调用 officecli 改过文件后同样要先执行 `officecli close <文件>`。

看图时重点查：标题与正文是否重叠、说明文字是否压住图片或相邻文字、内容是否全挤在一侧、页边装饰是否遮字、图片是否变形、形状是否带阴影。图表还要检查轴标签、长分类名、负值、图例、来源、单位和中文字体；SVG/PNG 兜底必须确认标签在 Office 或 LibreOffice 中仍清晰。几何底纹若被显式允许，必须确认文字、图表、表格、公式、页脚和页码都在保护区内且对比度足够。

### Hard（必须修）

- **越界**：元素超出页面。
- **文字溢出容器**：文字超出所在面板/卡片/文本框。
- **文字互相重叠**：两个文字块实际文字碰撞。
- **可读性**：正文与背景对比不足（小字 ≥ 4.5:1、大字 ≥ 3:1 的意识）；文字压在复杂图片上无底衬。
- **元素碰撞**：图形与图形叠压且破坏语义。
- **页眉页脚页码**：模板已声明的页眉、页脚、页码被遮挡/移动/删除。
- **图片损坏**：图片打不开、严重变形、拉伸。
- **关键元素缺失**：deck 要求的核心图形/表格/数据缺失。
- **信息一致性**：错别字、术语不一致、数据前后矛盾、图文不符、编造或无来源信息。
- **重叠遮蔽**：文字重叠、图形/卡片/列表交叠。

### Soft（明显不好才动；拿不准就保持）

- **垂直节奏过紧**：连续文本行距 < 1.05× 字号 → 放到 1.15–1.3×。
- **垂直节奏过空**：块内 > 大片无意义留白。
- **对齐漂移**：同列 x 或同行基线明显不在一条线上 → 对齐。
- **网格不均匀**：一排卡片间距相差 > 5% → 重新分布。因文字量不同而有依据地分配宽高不算网格失误；看图确认同组对齐、间距一致，较大区域没有改变阅读顺序或暗示不存在的数值比例。
- **高密度分组**：图与对应段落、阶段与渠道标签就近；论点和论据层级可区分。相邻组间距应大于组内间距，不能把别组图片或注释误读为本组依据。
- **CJK 字距过大**：letter-spacing 超过字号 5% → 收小。
- **装饰色竞争**：多个装饰色互相抢眼、与强调色打架 → 并入已有强调色。
- **强调焦点不符**：页面最显眼的不是 deck 里声明的主信息 → 调整。
- **图文关系**：图注离图超过 60px、图上有字无底衬、图片无用途 → 收紧/加底衬/删。
- **版式单调**：连续多页长得一样 → 换版式。

### 不触碰

- 配色、字体等**品牌级决策**不改（要改就回阶段三改渲染器副本的常量，全稿统一改）。采样参数、完整 palette/base 与覆盖项记在 `style.json`，以保存值复现。
- 本阶段小修限位置、字号（角色锚点 ±2pt 内）、间距、对齐、底衬调整。
- 小修无法消除溢出时，必须退回内容规划或模板选页阶段，重选容量合适的页型、拆分内容或调整结构，再重新跑全部检查；不能以“本阶段不做结构重排”为由交付已知问题。
- 章节标签按其容量写短标题，完整结论放进足够宽的正文标题区；不要持续缩小字体硬塞长标题。
- 文字提炼不得改变原意。

## 3. 修复回路（就地修复，不推倒重来）


| 问题层                                        | 修哪里                                                   | 然后                                   |
| ----------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------- |
| 内容/文案问题（错字、术语、数据、句子 AI 味） | 改 `deck.json`（必要时改 `STORY.md`）                    | 跑 `deck_check.py` → 重渲染 → 重校验 |
| 版式问题（重叠、越界、溢出、版式单调）        | 改 `deck.json` 的 layout/block 安排                      | 同上                                   |
| 渲染器 bug / 视觉规则不符                     | 改项目里的渲染器副本（`渲染器/render_pptx.py`、`text_measure.py`）；全局性缺陷同时改 skill 原件 | 重渲染该页或全稿                       |
| 模板继承问题                                  | 检查模板分析与页面映射是否正确，调整对应的模板原页 | 重新跑 `template_fill.py` |
| 公式显示异常                                  | 检查 `formula` 的 LaTeX，重新渲染后再跑 `formula.py` | 重渲染并重校验 |

每次修复后重跑：`渲染器/deck_check.py deck.json` → `渲染器/render_pptx.py` →（有公式）`formula.py` → `validate_pptx.py`，直到 **Hard 为零**（Soft 允许，但 `--strict` 场景除外）。
交付时如实说明资料缺口与假设。
